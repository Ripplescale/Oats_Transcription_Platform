# oats 0.8.10

Recording shutdown and recovery now share an owned lifecycle. A failed write or device error stops healthy-recording status, freezes the timer and reports the failure. Finish waits for device and source-file shutdown, with a bounded response and a retry path. A new recording remains blocked until the old device owner releases it. If a Windows driver remains stuck, an explicit restart action saves notes first and asks for confirmation that unfinished audio may be lost. Ordinary Quit finishes an active recording before exiting.

Recovery items now offer **Delete saved audio**, with a confirmation naming the recording. Deletion stops the selected recording's workers, removes only its known audio payloads, and preserves saved notes, transcript text and history. Interrupted deletion can be retried. Deleted audio is excluded from recovery and future worker launches.

Capture supports computer audio when the microphone fails to open. The existing eight-hour recording limit is now enforced during capture with an automatic finish, rather than producing a session that cannot be finalized later.

Transcription workers have supervised Stop and stall recovery. Cancellation first allows a checkpoint, then can terminate only the process tree owned by that job. Original audio, immutable runtime snapshots and completed checkpoints stay available. Deleting a meeting coordinates its worker shutdown and workflow removal so later work does not remain queued behind a deleted meeting.

Trelis dictation can commit stable words during continuous speech. It compares successive audio prefixes, retains a short uncertain tail and uses bounded overlapping windows for longer speech. Already typed words are not silently revised. If a revision or ambiguous overlap cannot be aligned safely, delivery pauses and retains text for review. Endpoint-detector failures are visible and do not silently disable all live output. Actual delay depends on model startup and device inference speed.

Automatic update checks can retry when networking returns after an offline launch. Successful checks still debounce repeated focus events; downloads and installation remain explicit choices.

Setup buttons now say **Install oats** and **Download for another PC**. The installation guide puts the usual installation path first and keeps developer commands separate. Setup retries count verified files and retained partial downloads instead of demanding the full space again. Before activating a new speech configuration, setup runs both engines on a short generated clip. A failed GPU check offers an explicit CPU retry. The current setup helper is embedded in the small bootstrap so reused immutable model parts do not silently retain an older check.

The release regression gate includes the complete Node component/library suite, including recording failure, guarded restart and recovery-audio deletion checks. Automated fixtures do not establish clean-PC microphone behavior, a particular GPU driver's reliability, or real speech accuracy/latency. Updater signing remains in place.
