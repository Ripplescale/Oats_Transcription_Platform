oats 0.8.12 fixes reopening an older copy after updating.

- Windows setup checks verified existing installations, legacy/current registry records, uninstall locations and existing oats/xx shortcuts before choosing its location. A recognised older installation can be upgraded in place instead of creating another copy.
- Existing Desktop, Start-menu and recognised taskbar shortcuts pointing to older oats copies are retargeted to the installed version. Launch arguments are preserved, and Windows short/long path aliases are normalised.
- Shortcuts to a newer oats version are left alone. Executable metadata is checked; unrelated products, incomplete installations and linked directories are excluded from automatic migration.
- Discovery and repair run inside the existing NSIS installer. No standalone migration executable, PowerShell process or script-host dependency is added.

Notes, recordings and models are preserved. In-place updates replace the old app normally; separate installation folders are not deleted by shortcut repair.

Existing users: About → Check for updates. Fully quit other oats copies before installing. This is signed with the existing oats updater identity; endpoint-security acceptance on a managed laptop still depends on its policy.
