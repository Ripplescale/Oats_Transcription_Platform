# oats 0.8.9

Trelis and Apex now prepare missing working folders before a transcription starts
or resumes. Earlier complete setup builds omitted the empty OpenVINO cache and
Apex CLI workspace, leaving both models unable to start despite valid model
files. The app repairs missing folders only within an existing complete-setup
package. It preserves model files, notes, recordings, existing cache contents,
worker settings and immutable job snapshots. Previously failed jobs can resume
from their saved audio after this update. Dictation preparation uses the same
Trelis cache guard.

Automatic update checks now run shortly after app startup and when the main
window regains focus or networking returns. They bypass the persisted 24-hour
background-check limit, with a short in-memory debounce for repeated focus
events. A recent check in a previous app session no longer hides an available
update until the following day. Checks remain metadata-only: downloads and
installation each require the user's choice, and the existing recording,
dictation and unsaved-note installation protections remain in place.

Users on 0.8.5 can check manually through About to receive this release. On the
external test laptop, update first, then resume or retry the failed transcript in
Tools → Transcription & versions. This is an app-only update; no model download
or repeated recording is required. The standalone Oats-Repair tool remains an
alternative for complete installations that need only the two work folders.

Regression checks cover fresh working-directory preparation, preservation of
existing data, rejection of missing paths outside the package, new-session
update checks despite a recent stored check, focus-event debouncing and
metadata-only notifications. Automated checks do not establish GPU-driver
compatibility, transcription accuracy, live latency, or success on the external
laptop before it retries its saved recording.
