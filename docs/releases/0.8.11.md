oats 0.8.11 fixes reopening an older copy after updating.

- Windows setup now checks verified existing installations, uninstall records and existing oats/xx shortcuts before choosing its location. An older recognised installation can be upgraded in place instead of creating a second copy.
- Existing Desktop, Start-menu and recognised taskbar shortcuts are retargeted to the installed version, including shortcuts pointing to a separate older copy. Existing launch arguments are preserved.
- Identification checks the executable's product and version metadata. Unrelated executables, incomplete installations and linked directories are excluded from automatic migration.
- The fix runs inside the normal Windows installer; it adds no migration executable, PowerShell process or script-host dependency.

Notes, recordings, models and separate installation folders are not deleted by shortcut repair. When setup upgrades in place, the old app executable is replaced normally. Separate copies remain on disk rather than risk deleting unrecognised files or data.

Existing users: About → Check for updates. Fully quit any other oats copies before installing. This release uses the existing oats updater signature; no Windows publisher certificate has been added.
